# MissingShip — alpha

The Missing Link (Kaze Emanuar, v2.0) running on the **Ship of Harkinian** engine.

This is a **mod + patched engine**, not a recompilation. ML's scene, room, collision and texture
data are repacked into an SoH `.o2r` archive; the engine is SoH 9.2.3 built from source with one
rendering fix. No ML machine code is executed.

## Running

```bash
./MissingShip.sh
```

`home/` is a self-contained `SHIP_HOME` — it never touches a normal SoH or ComboShip install.
It needs `home/oot.o2r`, generated by Ship of Harkinian from your own legitimate OoT NTSC 1.0 ROM.
Building the mod additionally requires an ML-patched ROM, which is **not** distributed here.

Boot goes straight to the file select. **Start a new file.**

## What works

- **25 ML scenes / 72 rooms** load, render and are walkable, with correct collision.
- **Textures**: all 1281 scene textures resolve (0 unresolved, 0 missing declarations).
- **Scene table ported** — every ML scene sits at its true vanilla scene ID.
- **Entrance table ported** — all 60 exit references remapped to equivalent vanilla entrances.
- **Area title cards ported** — ML's own place names ("Cluck Cluck Ranch", "Deku Grove", …).
- **New game** spawns into ML's real starting area.
- **Actors and objects restored** — ML reuses vanilla actors/objects, which SoH already ships.
  NPCs spawn and dialogue works.

## Known broken

- **Cutscenes do not work.** ML's scripts target ML's own rewritten dispatcher; vanilla's
  `Cutscene_ProcessCommands` either hangs or reads poison. Worked around, not fixed.
- **Start menu is SoH's, not ML's.** ML's file select is custom MIPS and cannot be ported as data.
- **Audio is vanilla.** ML's `Audiobank`/`Audioseq`/`Audiotable` are not ported, so ML's scene
  sequence IDs resolve against vanilla's table. Coherent, but not ML's soundtrack.
- **Minimaps are hidden by default** (`gCosmetics.HUD.Minimap.PosType = 4`). ML does not ship
  custom overworld minimaps -- 19 of its 20 are byte-identical to vanilla -- so the base game
  itself draws vanilla maps over ML's redrawn world. Hiding it is closer to correct than showing
  the wrong map. Re-enable in Cosmetics if you want it back.
- ML's **36 custom actor overlays and 18 custom objects** are not ported (they are N64 machine code).
- Scene slot 54 is vanilla's Stable — ML's occupant was moved to slot 52 to fix the game start.

## Why it is an .app bundle

MissingShip ships as `MissingShip.app` with its own identity (`com.missingship.MissingShip`),
not as a bare executable. macOS attributes per-app audio by bundle identity, so a bare Mach-O is
invisible to per-app volume tools (e.g. QuietDown) and to the accessibility app list.
`getMainBundlePath()` returns `[[NSBundle mainBundle] resourcePath]`, which is why `assets/` and
`soh.o2r` live in `Contents/Resources`. `SHIP_HOME` is set both by the launcher and by
`LSEnvironment` in `Info.plist`, so double-clicking the app works too.
The launcher kills any existing instance first (`pkill -x MissingShip` — `-f` would also match the
shell invoking it).

## The engine change

One fix, in `libultraship/src/fast/backends/gfx_metal.cpp`, `GfxRenderingAPIMetal::UploadTexture`:
skip the upload when `width == 0 || height == 0`. The importers compute
`height = sizeBytes / lineBytes`, and Metal treats a zero-dimension descriptor as fatal, so a single
malformed texture aborted the whole process. Stock 9.2.3 has no such check.

## Rebuilding the mod

```bash
cd pipeline && ./cycle.sh          # rebuild ROM, repack .o2r, install, launch, report
```

Knobs (all default to the correct behaviour; set to 1 only to restore old workarounds):
`ML_STRIP_ACTORS`, `ML_REMAP_OBJECTS`, `ML_FIX_SETTIMG_FMT`, `ML_SCRUB`, `ML_STRIP_CS`,
`ML_SKIP_FMT`, `ML_SKIP_SLOTS`, `ML_NO_START_FIX`.

## Legal

Contains no Nintendo assets and no Missing Link assets. Both an OoT ROM and an ML-patched ROM must
be supplied by the user. The Missing Link is by Kaze Emanuar; Ship of Harkinian is by HarbourMasters.

## Working from this repo (e.g. a cloud session)

This repo holds the pipeline, tools, docs and the engine changes as patches. It does **not** hold
ROMs or anything built from them (`*.z64`, `*.o2r`, `*.otr`, `ml_code.bin` are gitignored).

Engine: clone SoH 9.2.3 and apply the patches.

```bash
git clone --recursive https://github.com/HarbourMasters/Shipwright.git && cd Shipwright
git checkout cb71e22 && git submodule update --init --recursive
git apply ../MissingShip/docs/soh-missingship.patch
(cd ZAPDTR && git apply ../../MissingShip/docs/zapd-missingship.patch)
(cd libultraship && git apply ../../MissingShip/docs/libultraship-missingship.patch)
```

After editing the engine, regenerate `docs/soh-missingship.patch` as in `docs/PORTING_ACTORS.md` step 6.

Without the ROMs, code work (C ports from notes in `docs/`) still works, but the analysis tools
(`tools/*.py` need `tml_2_0.z64` and `PAL MQ (Debug).z64`) and the asset pipeline do not. Scripts
also hardcode this machine's paths (`/Volumes/MacMiniExternal/AI_Projects/...`).

Status and next steps: `docs/ML_ACTOR_INVENTORY.md` (actor todo list) and `docs/ENGINE_CHANGES.md`.
